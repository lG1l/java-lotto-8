## 요구 사항

---

### 1. 과제 진행 요구 사항

* 미션은 **로또** 저장소를 포크하고 클론하는 것으로 시작한다.
* **기능을 구현하기 전 `README.md`에 구현할 기능 목록을 정리**해 추가한다.
* Git의 커밋 단위는 앞 단계에서 `README.md`에 정리한 기능 목록 단위로 추가하며, **AngularJS Git Commit Message Conventions**을 참고해 커밋 메시지를 작성한다.
* 자세한 과제 진행 방법은 프리코스 진행 가이드 문서를 참고한다.

### 2. 기능 요구 사항

* **기능 목표**
  * 로또 구입, 발행, 당첨 번호 입력, 당첨 내역 및 수익률 출력을 포함하는 간단한 로또 발매기를 구현한다.

* **세부 사항**
  * 로또 번호의 숫자 범위는 **1~45**까지이며, 1개의 로또는 중복되지 않는 **6개**의 숫자를 뽑는다.
  * 당첨 번호 추첨 시 중복되지 않는 숫자 6개와 보너스 번호 1개를 뽑는다.
  * 로또 1장의 가격은 **1,000원**이다.
  * 로또 구입 금액을 입력하면 구입 금액에 해당하는 만큼 로또를 발행해야 한다.
  * **당첨 기준 및 금액**

    | 등수 | 일치 조건 | 상금 |
    | :--- | :--- | :--- |
    | 1등 | 6개 번호 일치 | 2,000,000,000원 |
    | 2등 | 5개 번호 + 보너스 번호 일치 | 30,000,000원 |
    | 3등 | 5개 번호 일치 | 1,500,000원 |
    | 4등 | 4개 번호 일치 | 50,000원 |
    | 5등 | 3개 번호 일치 | 5,000원 |
  * 수익률은 **소수점 둘째 자리에서 반올림**하여 출력한다. (ex. 62.5%)

* **예외 처리**
  * 사용자가 잘못된 값을 입력할 경우 **`IllegalArgumentException`**을 발생시킨다.
  * 에러 메시지는 **`"[ERROR]"`**로 시작하는 메시지를 출력하고, 해당 부분부터 입력을 다시 받는다.
  * 구현한 예외처리
    * 사용자 입력에서 정수가 아닌 값을 입력한 경우
    * 구매금액이 1000원 단위가 아닌 경우
    * 당첨번호 입력을 ,로 구분된 정수가 아닌 경우
    * 당첨번호 입력의 개수가 로또 개수와 일치하지 않은 경우
    * 당첨번호 입력에서 중복된 숫자가 있는 경우
    * 당범번호 입력에서 범위를 벗어난 경우
    * 보너스 번호 입력에서 당첨 번호를 입력한 경우

* 입출력 요구 사항
  * 입력
    * 로또 구입 금액을 입력 받는다. 구입 금액은 1,000원 단위로 입력 받으며 1,000원으로 나누어 떨어지지 않는 경우 예외 처리한다.
        ```
        14000
        ```
    * 당첨 번호를 입력 받는다. 번호는 쉼표(,)를 기준으로 구분한다.
        ```
        1,2,3,4,5,6
        ```
    * 보너스 번호를 입력 받는다.
        ```
        7
        ```

  * 출력

    * 발행한 로또 수량 및 번호를 출력한다. 로또 번호는 오름차순으로 정렬하여 보여준다.
        ```
        8개를 구매했습니다.
        [8, 21, 23, 41, 42, 43] 
        [3, 5, 11, 16, 32, 38] 
        [7, 11, 16, 35, 36, 44] 
        [1, 8, 11, 31, 41, 42] 
        [13, 14, 16, 38, 42, 45] 
        [7, 11, 30, 40, 42, 43] 
        [2, 13, 22, 32, 38, 45] 
        [1, 3, 5, 14, 22, 45]
        ```

    * 당첨 내역을 출력한다.
        ```
        3개 일치 (5,000원) - 1개
        4개 일치 (50,000원) - 0개
        5개 일치 (1,500,000원) - 0개
        5개 일치, 보너스 볼 일치 (30,000,000원) - 0개
        6개 일치 (2,000,000,000원) - 0개
        ```

    * 수익률은 소수점 둘째 자리에서 반올림한다. (ex. 100.0%, 51.5%, 1,000,000.0%)
        ```
        총 수익률은 62.5%입니다.
        ```

    * 예외 상황 시 에러 문구를 출력해야 한다. 단, 에러 문구는 "[ERROR]"로 시작해야 한다.
        ```
        [ERROR] 로또 번호는 1부터 45 사이의 숫자여야 합니다.
        ```

  * 실행 결과 예시
    ```
    구입금액을 입력해 주세요.  
    8000
    
    8개를 구매했습니다.

    [3, 5, 11, 16, 32, 38]  
    [5, 11, 16, 36, 38, 44]  
    [1, 8, 11, 31, 41, 42]  
    [13, 14, 16, 38, 42, 45]  
    [7, 11, 30, 40, 42, 43]  
    [2, 13, 22, 38, 42, 45]  
    [1, 3, 5, 14, 22, 45]
    
    당첨 번호를 입력해 주세요.  
    1,2,3,4,5,6
    
    보너스 번호를 입력해 주세요.  
    7
    
    당첨 통계
    ---  
    3개 일치 (5,000원) - 1개
    ```

### 3. 프로그래밍 요구 사항

* **JDK 21** 버전에서 실행 가능해야 한다.
* 프로그램 실행의 시작점은 `Application`의 `main()`이다.
* `build.gradle` 파일은 변경할 수 없으며, **제공된 라이브러리 이외의 외부 라이브러리는 사용하지 않는다.**
* 프로그램 종료 시 `System.exit()`을 호출하지 않는다.
* 프로그래밍 요구 사항에서 달리 명시하지 않는 한 파일, 패키지 등의 이름을 바꾸거나 이동하지 않는다.
* 자바 코드 컨벤션을 지키면서 프로그래밍한다. (**Google Java Style Guide** 원칙)
* `indent(들여쓰기) depth`를 2까지만 허용한다.
* 3항 연산자를 쓰지 않는다.
* 함수(또는 메서드)가 한 가지 일만 하도록 최대한 작게 만들어라. (15줄 이하로 구현)
* JUnit 5와 AssertJ를 이용하여 기능 목록이 정상적으로 작동하는지 테스트 코드로 확인한다. (UI로직을 제외한 단위 테스트 작성)
* `else` 예약어를 쓰지 않는다. (`switch/case`도 허용하지 않음)
* Java Enum을 적용하여 프로그램을 구현한다.
* `camp.nextstep.edu.missionutils.Randoms` 및 `Console` API를 사용하여 구현해야 한다.
    * **Random 값 추출**: `Randoms.pickUniqueNumbersInRange()` 활용
    * **사용자 입력**: `Console.readLine()` 활용
* 제공된 **`Lotto` 클래스**를 사용하여 구현해야 하며, `numbers` 이외의 필드(인스턴스 변수)를 추가할 수 없다.

## 테스트 실행 가이드

---

미션 제출 전, 구현한 기능이 요구 사항을 모두 만족하는지 다음 명령어로 확인한다.

1. **Java 버전 확인 (JDK 21):**
    ```terminal
    java -version
    ```
2.  **테스트 실행:**
    * Mac 또는 Linux:
        ```bash
        ./gradlew clean test
        ```
    * Windows:
        ```bash
        gradlew.bat clean test //또는
        .\gradlew.bat clean test
        ```

모든 테스트 통과 시 다음과 같은 메시지가 출력됩니다.

```
BUILD SUCCESSFUL in 0s 
```
